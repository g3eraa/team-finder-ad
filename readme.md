# TeamFinder

[![CI/CD](https://github.com/g3eraa/team-finder-ad/actions/workflows/ci.yml/badge.svg)](https://github.com/g3eraa/team-finder-ad/actions/workflows/ci.yml)

Платформа, где разработчики, дизайнеры и другие специалисты находят команду для pet-проектов:
публикуют идеи, присоединяются к чужим проектам и знакомятся с участниками.

**Вариант 2:** навыки пользователей и фильтрация участников по навыкам.

**Стек:** Django 5.2, PostgreSQL 16, gunicorn, Caddy, Docker Compose, Pillow, python-decouple.

## Запуск

Есть два способа. Для проверки проще первый: нужен только Docker.

### Способ 1. Весь проект в Docker

```bash
git clone git@github.com:g3eraa/team-finder-ad.git
cd team-finder-ad
cp .env_example .env
docker compose up -d --build
docker compose exec web python manage.py loaddata test_data
docker compose exec web python manage.py createsuperuser   # спросит email, имя, фамилию и пароль
```

- Сайт: <http://localhost/>
- Админка: <http://localhost/admin/>

| Контейнер            | Что делает                                                                  |
|----------------------|-----------------------------------------------------------------------------|
| `teamfinder_db`      | PostgreSQL 16, данные в volume `postgres_data`                              |
| `teamfinder_web`     | Django под gunicorn; при каждом старте выполняет `migrate` и `collectstatic` |
| `teamfinder_gateway` | Caddy на порту 80: отдаёт `/static/` и `/media/`, остальное передаёт в `web` |

В контейнере `web` всегда `DEBUG=False`, как на боевом сервере, поэтому включены валидаторы
паролей. Если порт 80 занят, запустите с другим: `GATEWAY_PORT=8080 docker compose up -d`.
Остановить — `docker compose down`, удалить вместе с данными — `docker compose down -v`.

### Способ 2. Django локально, база в Docker

Нужен Python **3.10–3.13**: на 3.14 зависимости из `requirements.txt`
(Django 5.2.4, psycopg2-binary 2.9.10) официально не поддерживаются.

```bash
git clone git@github.com:g3eraa/team-finder-ad.git
cd team-finder-ad
python3 -m venv venv
source venv/bin/activate              # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env_example .env

docker compose up -d db               # только PostgreSQL
python manage.py migrate
python manage.py loaddata test_data
python manage.py createsuperuser
python manage.py runserver
```

- Сайт: <http://127.0.0.1:8000/>
- Админка: <http://127.0.0.1:8000/admin/>

### Переменные `.env`

Значения из `.env_example` подходят для локальной проверки, менять ничего не нужно.

| Переменная                    | Назначение                                                                  |
|-------------------------------|-----------------------------------------------------------------------------|
| `DJANGO_SECRET_KEY`           | Секретный ключ Django                                                       |
| `DJANGO_DEBUG`                | Режим отладки для способа 2. При `True` Django сам раздаёт `media/`, а валидаторы паролей выключены |
| `DJANGO_ALLOWED_HOSTS`        | Домены и IP сайта через запятую, по умолчанию `localhost,127.0.0.1`         |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Нужно на сервере с HTTPS: `https://домен`                                   |
| `DJANGO_SECURE_COOKIES`       | `True` на сервере с HTTPS — cookie сессии передаются только по HTTPS        |
| `POSTGRES_DB`                 | Имя базы данных                                                             |
| `POSTGRES_USER`               | Пользователь PostgreSQL                                                     |
| `POSTGRES_PASSWORD`           | Пароль пользователя PostgreSQL                                              |
| `POSTGRES_HOST`               | Адрес БД для способа 2, `localhost`. В Docker подставляется `db`            |
| `POSTGRES_PORT`               | Порт БД на машине. По этому же порту `docker compose` публикует контейнер   |
| `TASK_VERSION`                | Номер варианта, выбирает папку шаблонов. Здесь `2` → `templates_var2/`      |

В примере `POSTGRES_PORT=5436`, поэтому база не конфликтует с PostgreSQL,
если он уже запущен на стандартном порту `5432`.

## Что проверить

Для проверки участия в проектах и прав доступа удобно войти под двумя тестовыми аккаунтами:
например, `anna@example.com` в обычном окне браузера и `maxim@example.com` — в режиме инкогнито.

1. **Регистрация** — `/users/register/`: имя, фамилия, email, пароль.
   После отправки формы открывается страница входа.
   Пользователю автоматически создаётся аватарка: первая буква имени на однотонном фоне.
2. **Вход и выход** — `/users/login/` по email и паролю. Неверная пара даёт ошибку
   «Неверный email или пароль». Выход — пункт «Выйти» в меню под аватаркой.
3. **Проекты:**
   - «Создать проект» в шапке → после публикации открывается страница проекта, автор уже в участниках;
   - автор видит «Редактировать» (поля предзаполнены) и «Завершить проект» (статус меняется без перезагрузки);
   - другой пользователь видит «Участвовать» / «Отказаться от участия», список участников обновляется без перезагрузки;
   - гость видит «Войти, чтобы участвовать»;
   - на главной карточки идут от новых к старым, по 12 на странице.
4. **Профиль** — `/users/<id>/`: ФИ, аватар, описание, контакты, проекты пользователя.
   Владелец видит «Редактировать» и «Добавить проект».
5. **Навыки (вариант 2)** — в своём профиле «+ Добавить навык»:
   - при вводе появляются до 10 подсказок по алфавиту, по ним можно ходить стрелками;
   - Enter добавляет ровно введённый навык; если такого нет, можно выбрать «Создать «…»»;
   - навыки добавляются и удаляются крестиком без перезагрузки;
   - в чужом профиле навыки только для просмотра.
6. **Участники и фильтр (вариант 2)** — `/users/list/`:
   - панель тегов со всеми навыками;
   - клик по тегу формирует `?skill=<название>` и оставляет только пользователей с этим навыком
     (например, `C++` — только София, `Python` — Анна и София);
   - активный тег подсвечен, есть «Сбросить»;
   - по 12 пользователей на странице, новые сверху.
7. **Редактирование профиля** — меню → «Редактировать профиль»:
   - телефон принимается в формате `8XXXXXXXXXX` или `+7XXXXXXXXXX`, хранится как `+7XXXXXXXXXX`;
   - один номер нельзя указать двум пользователям, даже если записан в разных форматах;
   - ссылка GitHub должна вести на `github.com`;
   - ошибка показывается под тем полем, к которому относится.
8. **Смена пароля** — меню → «Сменить пароль». После смены пользователь остаётся в системе.
9. **Поделиться** — иконка на странице профиля и проекта копирует ссылку.
10. **Админка** — `/admin/`:
    - смена пароля любому пользователю (ссылка в поле «Пароль»);
    - блокировка — снять галочку «Активен», заблокированный не сможет войти;
    - удаление пользователей, редактирование и удаление любых проектов.
11. **Телефон** — все страницы адаптированы под ширину от 360 px.

## Тесты и CI/CD

```bash
python manage.py test   # 32 теста: страницы, права, JSON-эндпоинты, админка, тестовые данные
pip install flake8
flake8                  # PEP 8, длина строки 100 — настройки в setup.cfg
```

Тестам нужна запущенная база (`docker compose up -d db`): Django создаёт и после прогона
удаляет отдельную базу `test_team_finder`. Аватарки, созданные в тестах, пишутся во временную
папку, а не в `media/`. В Docker тесты запускаются так: `docker compose exec web python manage.py test`.

GitHub Actions ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) на каждый push и
pull request в `main` и `develop`:

1. `flake8`;
2. `manage.py check`, проверка несозданных миграций и тесты на PostgreSQL 16;
3. сборка Docker-образов `web` и `gateway`; при push в `main` они публикуются в GitHub Container Registry;
4. деплой на сервер по SSH — включается, когда сервер настроен по [DEPLOY.md](DEPLOY.md).

## Отступления от рекомендаций (`docs/4_Рекомендации_по_реализации.md`)

| Что | Как сделано | Почему |
|---|---|---|
| Редирект после регистрации | на страницу входа, без автоматического входа | так требуют ТЗ и чек-лист; рекомендации предлагали сразу авторизовать |
| Ответ `POST /users/<id>/skills/add/` | `{"id", "name", "skill_id", "created", "added"}` | `skill_id`, `created`, `added` — из рекомендаций, а `id` и `name` читает готовый `static/js/skills.js` |
| Поле `User.skills` | `ManyToManyField` | у пользователя много навыков, а у навыка много пользователей; внешний ключ так не умеет |
| Поле `User.phone` | необязательное (`null=True`), уникальное | при регистрации телефон не запрашивается; `NULL` у нескольких пользователей не нарушает уникальность |
| Названия навыков | уникальны без учёта регистра, сортируются по алфавиту без учёта регистра | чтобы не появлялись дубли `Python` / `python` |
| JSON-эндпоинты | без входа отвечают JSON с кодом 401/403, а не редиректом | `fetch` в JS ждёт JSON, HTML-страница входа ломала обработку ответа |
| Список участников | заблокированные (`is_active=False`) не показываются | блокировка из админки скрывает аккаунт с сайта |
| Участие автора | автор не может выйти из своего проекта | автор всегда в участниках, кнопки участия у него нет |
| `LANGUAGE_CODE` | `ru-ru` | стандартные ошибки форм и админка на русском, как и весь интерфейс |
| Длина пароля | свой `users.validators.MinimumLengthValidator` | в русском переводе Django 5.2 нет этого сообщения, и оно выводилось по-английски |
| `docker-compose.yml` | весь проект: `db`, `web`, `gateway`; порт БД берётся из `POSTGRES_PORT` | раньше compose поднимал только базу и всегда публиковал `5432`, а пример `.env` указывает `5436` |

### Правки в шаблонах, CSS и JS заготовки

По результатам аудита интерфейса (доступность WCAG 2.2 и вёрстка на телефоне):

| Где | Что исправлено |
|---|---|
| `base.html` | не было `<meta name="viewport">` — на телефоне сайт отображался уменьшенной копией десктопа; добавлены `<main>` и ссылка «Перейти к содержимому» |
| CSS | медиазапросы: шапка в две строки, сетки проектов и участников перестраиваются, профиль складывается в колонку |
| `includes/header.html`, `header.js` | меню пользователя открывалось только мышью (`<a>` без `href`) — теперь это кнопка с `aria-expanded`, закрывается по Escape; скрытое меню больше не ловит фокус Tab и не выводится гостям (у гостя в нём была ссылка на `/users/None/`) |
| `static/js/skills.js` | Enter на «Java» добавлял первую подсказку «JavaScript»; название навыка вставлялось через `innerHTML` (XSS через навык, созданный другим пользователем) |
| `static/js/projects.js` | подтверждение перед завершением проекта; карточка участника собирается без `innerHTML` |
| Формы регистрации, профиля и проекта | ошибки выводились одним блоком внизу формы — теперь под своим полем и связаны с ним через `aria-describedby`; добавлены `autocomplete` и подсказки формата |
| `users/participants.html` | ссылка фильтра `?skill={{ skill\|urlencode }}` — без экранирования не работали навыки `C++`, `C#` и названия с пробелами |
| `404.html`, `403.html`, `500.html` | вместо английской «Not Found» без навигации — страницы в стиле сайта |
| Контраст | даты и счётчики участников `#888`/`#777` (3.54:1 и 4.48:1) → `#6b7280` (4.83:1); текст ошибок `red` (4.0:1) → `#d93025` (4.78:1) |
| Прочее | заголовки страниц стали `<h1>`; у кнопок «Поделиться» появилось название; крестик удаления навыка увеличен до 24×24 px; «Создать проект» на главной видят только авторизованные; закрытый проект отмечен серым бейджем |

## Структура

```text
team_finder/                   настройки, корневые URL
users/                         пользователь (вход по email), навыки, профиль, генерация аватарок, тесты
projects/                      проекты, участие, завершение, тесты
templates_var2/                HTML-шаблоны варианта 2, страницы ошибок 403/404/500
static/                        CSS, JS, шрифт, картинка аватара по умолчанию
fixtures/                      тестовые данные для loaddata
media/avatars/                 аватарки; в git только аватарки тестовых пользователей
gateway/                       образ Caddy: Caddyfile со статикой, медиа и HTTPS
Dockerfile, entrypoint.sh      образ Django: gunicorn, migrate и collectstatic при старте
docker-compose.yml             локальный запуск: db + web + gateway
docker-compose.production.yml  сервер: готовые образы из GitHub Container Registry
.github/workflows/ci.yml       CI/CD: flake8, тесты, сборка образов, деплой
setup.cfg                      настройки flake8
```
