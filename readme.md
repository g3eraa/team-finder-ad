# TeamFinder

Платформа, где разработчики, дизайнеры и другие специалисты находят команду для pet-проектов:
публикуют идеи, присоединяются к чужим проектам и знакомятся с участниками.

**Вариант 2:** навыки пользователей и фильтрация участников по навыкам.

**Стек:** Python 3.10–3.13, Django 5.2, PostgreSQL 16 в Docker Compose, Pillow, python-decouple.

Схемы архитектуры, моделей и всех эндпоинтов — в [ARCHITECTURE.md](ARCHITECTURE.md).

---

## Запуск

Нужны Python **3.10–3.13** и Docker. На Python 3.14 зависимости из `requirements.txt`
(Django 5.2.4, psycopg2-binary 2.9.10) официально не поддерживаются.

### 1. Клонировать репозиторий и создать окружение

```bash
git clone git@github.com:g3eraa/team-finder-ad.git
cd team-finder-ad

python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Создать `.env`

```bash
cp .env_example .env
```

Значения из примера подходят для локальной проверки, менять ничего не нужно.

| Переменная          | Назначение                                                                 |
|---------------------|----------------------------------------------------------------------------|
| `DJANGO_SECRET_KEY` | Секретный ключ Django                                                      |
| `DJANGO_DEBUG`      | Режим отладки. При `True` Django раздаёт загруженные аватарки из `media/` |
| `POSTGRES_DB`       | Имя базы данных                                                            |
| `POSTGRES_USER`     | Пользователь PostgreSQL                                                    |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL                                             |
| `POSTGRES_HOST`     | Адрес сервера БД, локально `localhost`                                     |
| `POSTGRES_PORT`     | Порт БД на машине. По этому же порту `docker compose` публикует контейнер  |
| `TASK_VERSION`      | Номер варианта, выбирает папку шаблонов. Здесь `2` → `templates_var2/`     |

В примере `POSTGRES_PORT=5436`, поэтому база не конфликтует с PostgreSQL,
если он уже запущен на стандартном порту `5432`.

### 3. Запустить PostgreSQL

```bash
docker compose up -d
```

Данные хранятся в volume `postgres_data` и не теряются при перезапуске контейнера.
Остановить базу — `docker compose down`, удалить вместе с данными — `docker compose down -v`.

### 4. Применить миграции и создать администратора

```bash
python manage.py migrate
python manage.py createsuperuser   # спросит email, имя, фамилию и пароль
```

### 5. Запустить сервер

```bash
python manage.py runserver
```

- Сайт: <http://127.0.0.1:8000/> (перенаправляет на список проектов `/projects/list/`)
- Админка: <http://127.0.0.1:8000/admin/>

## Что проверить

Для проверки участия в проектах и прав доступа удобно держать два аккаунта:
один в обычном окне браузера, второй — в режиме инкогнито.

1. **Регистрация** — `/users/register/`: имя, фамилия, email, пароль.
   После отправки формы открывается страница входа.
   Пользователю автоматически создаётся аватарка: первая буква имени на однотонном фоне.
2. **Вход и выход** — `/users/login/` по email и паролю. Неверная пара даёт ошибку
   «Неверный email или пароль». Выход — пункт «Выйти» в меню под аватаркой.
3. **Проекты:**
   - «Создать проект» в шапке → после публикации открывается страница проекта, автор уже в участниках;
   - автор видит «Редактировать» (поля предзаполнены) и «Завершить проект» (статус меняется без перезагрузки);
   - другой пользователь видит «Участвовать» / «Отказаться от участия», список участников обновляется без перезагрузки;
   - на главной карточки идут от новых к старым, по 12 на странице.
4. **Профиль** — `/users/<id>/`: ФИ, аватар, описание, контакты, проекты пользователя.
   Владелец видит «Редактировать» и «Добавить проект».
5. **Навыки (вариант 2)** — в своём профиле «+ Добавить навык»:
   - при вводе появляются до 10 подсказок по алфавиту;
   - если такого навыка нет, можно выбрать «Создать «…»»;
   - навыки добавляются и удаляются крестиком без перезагрузки;
   - в чужом профиле навыки только для просмотра.
6. **Участники и фильтр (вариант 2)** — `/users/list/`:
   - панель тегов со всеми навыками;
   - клик по тегу формирует `?skill=<название>` и оставляет только пользователей с этим навыком;
   - активный тег подсвечен, есть «Сбросить»;
   - по 12 пользователей на странице, новые сверху.
7. **Редактирование профиля** — меню → «Редактировать профиль»:
   - телефон принимается в формате `8XXXXXXXXXX` или `+7XXXXXXXXXX`, хранится как `+7XXXXXXXXXX`;
   - один номер нельзя указать двум пользователям, даже если записан в разных форматах;
   - ссылка GitHub должна вести на `github.com`.
8. **Смена пароля** — меню → «Сменить пароль». После смены пользователь остаётся в системе.
9. **Поделиться** — иконка на странице профиля и проекта копирует ссылку.
10. **Админка** — `/admin/`:
    - смена пароля любому пользователю (ссылка в поле «Пароль»);
    - блокировка — снять галочку «Активен», заблокированный не сможет войти;
    - удаление пользователей, редактирование и удаление любых проектов.

## Отступления от рекомендаций (`docs/4_Рекомендации_по_реализации.md`)

| Что | Как сделано | Почему |
|---|---|---|
| Редирект после регистрации | на страницу входа, без автоматического входа | так требуют ТЗ и чек-лист; рекомендации предлагали сразу авторизовать |
| Ответ `POST /users/<id>/skills/add/` | `{"id", "name", "skill_id", "created", "added"}` | `skill_id`, `created`, `added` — из рекомендаций, а `id` и `name` читает готовый `static/js/skills.js` |
| Поле `User.skills` | `ManyToManyField` | у пользователя много навыков, а у навыка много пользователей; внешний ключ так не умеет |
| Поле `User.phone` | необязательное (`null=True`), уникальное | при регистрации телефон не запрашивается; `NULL` у нескольких пользователей не нарушает уникальность |
| Названия навыков | уникальны без учёта регистра, сортируются по алфавиту без учёта регистра | чтобы не появлялись дубли `Python` / `python` |
| Шаблон `users/participants.html` | ссылка фильтра `?skill={{ skill\|urlencode }}` | без экранирования не работали навыки `C++`, `C#` и названия с пробелами |
| JSON-эндпоинты | без входа отвечают JSON с кодом 401/403, а не редиректом | `fetch` в JS ждёт JSON, HTML-страница входа ломала обработку ответа |
| Список участников | заблокированные (`is_active=False`) не показываются | блокировка из админки скрывает аккаунт с сайта |
| Участие автора | автор не может выйти из своего проекта | автор всегда в участниках, кнопки участия у него нет |
| `LANGUAGE_CODE` | `ru-ru` | стандартные ошибки форм и админка на русском, как и весь интерфейс |
| `docker-compose.yml` | порт берётся из `POSTGRES_PORT` в `.env` | раньше compose всегда публиковал `5432`, а пример `.env` указывает `5436` |

## Структура

```text
team_finder/      настройки, корневые URL
users/            пользователь (вход по email), навыки, профиль, генерация аватарок
projects/         проекты, участие, завершение
templates_var2/   HTML-шаблоны варианта 2
static/           CSS, JS, шрифт, картинка аватара по умолчанию
media/avatars/    аватарки пользователей
```
